The fix queued for #4471 is the parser fix. It does nothing for the hint or one-day reports: they now have their own tickets.

What each problem is

parser — the shared parser reads every date month first. Day-first tenants get day and month swapped: 7 April becomes 4 July.

hint — booking-v3 prints MM/DD/YYYY under its date field. People type month first, as told, and the form reads the value the tenant’s way. Same symptom as parser, different code, different fix.

one-day — the reports the desk read as a one-day move (desk-notes.json). Their bodies describe a date shifted by one day, or different days in different time zones, not a swap. Their tenants would file them under parser, but the parser fix will not touch them. Likely time-zone handling; the reports do not prove it.

How a report is placed

  1. Count each report once: the export pages overlap, so the same id can appear twice.
  2. A report the desk read as a one-day move (desk-notes.json) is one-day.
  3. Otherwise ask the tenant, not the reporter’s browser (causes.ts): a day-first tenant on a booking-v3 form is hint; every other day-first report is parser.

Intake’s tag is not used. It is a guess from the reporter’s browser and often names the wrong cause: compare the “tagged as” column above.

For the desk

  • Merge into a ticket only reports with the same cause, not the same subject.
  • When a new date report comes in, place it with the steps above and add it to that cause’s ticket.
